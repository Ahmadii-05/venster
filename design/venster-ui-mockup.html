React effect fires in an infinite loop

Summary

A useEffect that updates state it also depends on re-runs on every render, producing an infinite update loop and pegging the CPU. The fix is to correct the dependency array and derive state instead of mirroring it.

Root cause

The effect wrote to a state value that was listed in (or implied by) its dependency array. Each write triggered a re-render, which re-ran the effect, which wrote again — an unterminated cycle. Object/array dependencies created inline also change identity every render, defeating referential equality.

Solution

Remove the self-referential dependency and compute derived values during render (or with useMemo) rather than storing them in state. When you must depend on an object, memoize it or depend on a primitive field. Use the functional setState(prev => …) form so the effect no longer needs the current value as a dependency.

Synthesized answer

A 401 on refresh usually means the refresh token is being validated against a different signing secret than the one that issued it — most often because JWT_SECRET wasn't set, so the app fell back to a per-boot default and every restart invalidated existing tokens [1]. A second common cause is clock skew between services pushing the token just past exp [2].

Fix: pin a single JWT_SECRET across every instance and environment, and verify the refresh endpoint reads it from config rather than regenerating one at startup [1]. Add a small leeway to expiry validation to absorb skew [2].

1JWT default secret regenerated on each boot → all tokens invalid after restart
2Token expiry validation needs leeway for cross-service clock skew
